課題

バックアップは思った以上に漏れます。

HTTPS は通信中のデータを保護します。しかし DB ダンプ、盗まれたバックアップ、SQL インジェクションは保存時のデータを露出します。フィールド自体を暗号化しない限り。

Encrypted Fields なし

メールと注文が平文で残る

すべての DB ダンプ、バックアップ、分析エクスポートに、顧客の氏名・メール・電話番号が読める形で含まれます。

ハッシュだけでは不十分

検索とログインが壊れる

一方向ハッシュは値を守りますが、完全一致・部分一致検索や get_user_by() を動かす必要があります。

自作暗号

ローテーションと移行は危険

独自のキー管理は、ローテーション、移行、ロールバックを誤りやすくします。

得られるもの

暗号ライブラリだけでなく、具体的な成果。

保存時

DB ダンプで PII を読めない

宣言したフィールドは enc:v2:… として保存され、キーは wp-config または DB 外のファイルに残ります。

書き換え不要

WordPress API はそのまま

get_post_meta()、get_user_meta()、WooCommerce、ACF はアプリにプレーンテキストを返します。

検索可能

ブラインドインデックス検索とログイン

完全一致・部分一致検索、get_user_by()、email_exists()、トークン化ログインが動き続けます。

運用

安全な移行とローテーション

スキャン、ドライラン、移行、verify --full、ロールバック、再インデックス、2 フェーズのキーローテーションを WP-CLI で。

連携

WooCommerce、フォーム、多言語

注文メタ/住所インデックス、CF7+Flamingo、ACF、Polylang、マルチサイトをラボでテスト済み。

オープンソース

GPL-2.0、ロックインなし

ソース、変更履歴、リリースは GitHub。コアパッチなし、キーはあなたのもの。

データベースからの実際の証拠

合成テストデータのみ。実 PII はありません。キー ID は表示しますが、キーは表示しません。

これはプラグインの公開ランディングページです。スクリーンショットは PII を除いた合成テストデータを使用しており、WordPress デモ自体は公開していません。

設計

デフォルト拒否: 宣言したフィールドだけを暗号化。コアパッチなし、サードパーティプラグインのパッチなし。

wp-config.php、設定ファイル、フィルター、管理画面でエンティティ/メタ/カラムを宣言。

🔐

AES-256-GCM

テキストはランダム化、メール/ログインは SIV 決定論的。等価検索が平文を露出せずに機能します。

対象

実際の WordPress データのために。

検索、ログイン、通常の管理画面を犠牲にせず PII を保護したい代理店、ストアオーナー、会員サイト向け。

WooCommerce ストア

請求/配送フィールドと住所インデックスを暗号化し、注文検索と顧客ルックアップを維持。

会員・ユーザーサイト

ログイン/メールカラムをトークン化し、認証、パスワードリセット、WP-CLI ユーザー管理を維持。

フォーム、ACF、CRM メタ

宣言したフォーム/ACF フィールドを暗号化し、メールをブラインドインデックスで検索。Flamingo の送信も利用可能。

レガシー移行

レガシー暗号文を読み取り、v2 へ移行し、全行を検証して 2 フェーズでキーをローテーション。

インストール

PHP 8.0+、WordPress 6.4+、OpenSSL が必要です。既存データを移行する前に DB をバックアップしてください。

01

プラグインをインストールし、KEC_KEY + KEC_TOKEN_SECRET を設定。

02

KEC_FIELDS に必要なフィールドだけを宣言（デフォルト拒否）。

03

scan → migrate → verify --full を実行し、検索を再インデックス。

git clone https://github.com/thiennhant95/wp-encrypted-fields.git
cp -r wp-encrypted-fields wp-content/plugins/
wp plugin activate wp-encrypted-fields

# wp-config.php（wp-settings.php の require より前）
define('KEC_KEY', 'base64:REPLACE_WITH_32_BYTE_KEY');
define('KEC_TOKEN_SECRET', 'base64:REPLACE_WITH_STABLE_SECRET');
define('KEC_FIELDS', [
    'user' => [
        'columns' => [
            'user_login' => ['type' => 'login', 'max_length' => 60, 'search' => true],
            'user_email' => ['type' => 'email', 'max_length' => 100, 'search' => true],
        ],
        'meta' => ['first_name' => ['type' => 'text', 'search' => true]],
    ],
    'post' => [
        'post_types' => ['shop_order'],
        'meta' => [
            '_billing_email' => ['type' => 'email', 'search' => true],
            '_billing_address_index' => ['type' => 'text', 'search' => true],
        ],
    ],
]);

wp kec scan
wp kec migrate --backup-confirmed
wp kec verify --full

FAQ

購入前のよくある質問

HTTPS/SSL の代わりになりますか？

いいえ。HTTPS は通信中のデータを保護します。Encrypted Fields は宣言したフィールドを保存時に保護し、DB ダンプや盗まれたバックアップでも露出しません。

WooCommerce の注文検索はまだ動きますか？

はい、宣言した検索可能フィールドについて。プラグインは WooCommerce の SQL 検索から暗号化カラムを除外し、ブラインドインデックス結果をマージします。v1 では HPOS を無効にする必要があります。

get_user_by()、email_exists()、ログインは動きますか？

はい。ログイン/メールカラムはブラインドインデックストークンを保存し、生の等価/IN 検索は書き換えられ、認証フックがトークンを平文に戻します。

キーを失ったら？

キーなしでは暗号化値を復元できません。wp-config/キーファイルをバックアップし、キーを DB 外に保存し、変更前にローテーションを演習してください。

暗号化されないものは？

post_content/post_title、wp_options、アダプターのないカスタムテーブル。宣言したメタで平文のまま残るものは wp kec verify --full が報告します。

無料ですか？

はい。GPL-2.0-or-later、ソースとリリースは GitHub。有料プランやキー預託はありません。

はじめる

顧客 PII を保護する準備はできましたか？

プラグインをインストールし、必要なフィールドを宣言し、公開前に verify --full を実行してください。
